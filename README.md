# ヤマメ養殖管理アプリ

株式会社Adelo 社内用。ロット・池・給餌・死亡・成長測定を記録し、現在匹数・総重量・推奨給餌量・原価を自動計算する。

## 進め方
| Phase | 内容 | 状態 |
| --- | --- | --- |
| 1 | プロジェクト作成、Cloudflare/D1、DBスキーマ、マイグレーション、初期マスターデータ | 完了 |
| 2 | 共通パスコード、導入登録、今日の記録（給餌・水温・摂餌・死亡・取消） | 実装済み |
| 3 | ダッシュボード | 未着手 |
| 4 | 成長測定 | 未着手 |

## 公開までの手順（ターミナル不要）
1. GitHub にプライベートリポジトリ `yamame-app` を作り、このコードを置く
2. Cloudflare アカウントを作る
3. Cloudflare の「ストレージとデータベース → D1」でデータベース `yamame-db` を作成し、Database ID を `wrangler.jsonc` の `database_id` に入れる
4. Cloudflare の「Workers & Pages → 作成 → リポジトリをインポート」で GitHub の `yamame-app` を選ぶ
   - ビルドコマンド: 空欄
   - デプロイコマンド: `npm run deploy`
5. 発行された URL を開き、「接続状態 OK」と池8つ・ロット A-20261016 が表示されることを確認
6. 実データを入れる前に Cloudflare Access でログイン保護をかける

以後は main ブランチに push するたびに、自動でマイグレーション適用→デプロイされる。

## データについて
- スキーマ: `migrations/0001_initial_schema.sql`
- 初期データ: `migrations/0002_initial_master_data.sql`（池8つ、給餌率1%/日、餌550円/kg、仮の成長率0.91%/日、ロットA-20261016）
- 初回ロットの池への導入（どの池に何匹）は、初期配置が決まってから画面で登録する

## バックアップ
- D1 の時点復元（Time Travel）
- 日次の自動エクスポート（Phase 2 で追加予定）
- 画面からの CSV 出力（Phase 3 以降）

## パスコード
- Cloudflare の yamame-app → 設定 → 変数とシークレット で `APP_PASSCODE` を「シークレット」として登録する
- 変更すると、全端末のログインが無効になり、新しいパスコードでの再ログインが必要になる
- 未設定の間はアプリに入れない（安全側に倒している）
